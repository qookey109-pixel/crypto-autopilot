# Validated complete-tape inputs V0.1

The disabled prepaid Cloud Paper runtime wraps the existing Pionex client before its complete-tape feed aggregates lifecycle inputs. Every returned trade's price and size and every order-book level's price and size must be finite and positive. Invalid data stops with a stable review reason before a market frame can advance an open position. A valid feed preserves the same two provider requests and source; other client methods are delegated unchanged.

A nonfinite intermediate trade price can otherwise be ignored by ordinary min/max while finite first and last trades produce an apparently valid frame. This guard does not establish tape completeness, provider accuracy, strategy qualification or production activation. The existing saturation, gap, freshness, budget and frozen source boundaries remain in force.
